Evolution of The Robot Services Exchange

A technical history of the protocol, 2025-08-10 → 2026-09-17

This note is a reading of the git history of theservicesexchange (262 commits on main, about 176k insertions) from the first commit on 10 August 2025 through 17 September 2026. It is written for people who will want the numbers and the failed experiments, not a slogan. The marketplace that exists today is small and specific: a buyer posts a priced, expiring request; a provider calls POST /grab_job; an LLM is asked whether those capabilities cover this job rather than a neighboring one; both sides sign when the work is done; money never sits on the platform. How we got a system that looks that simple is the subject of the next three pages.

1. The first commit already had the loop

87a45fa on 10 August 2025 is a Flask API and a pile of JSON documents (accounts, bids, jobs, tokens) with no SQL database. Persistence later moved onto DigitalOcean Spaces, which is S3-compatible JSON, but the shape did not change: you read and write objects by id, and any index is another object. People post bids on the public website; robots call rse-api.com. Both parties have always had to sign before a job is completed, and a successful grab has always started a cooldown that is fifteen minutes today. Reputation is a mean of stars shrunk toward 2.5, so a single five-star rating does not look like a long record. Those pieces were in place before most of the product around them existed.

The work that followed was almost entirely about three other things. A seat is the scarce object that, when the gate is on, authorizes a grab and stamps supply identity on the job; seats are not money, and the platform still does not hold funds. The matching function is the only place an LLM is allowed to decide who works. Around that core we added, and sometimes removed, a mobile app, cooperation APIs, a catalog, investor documents, and two quite different implementations of title.

2. From a general exchange to robot labor

The repository opened as the “Service Exchange (SEX) Protocol,” which was meant to be a general marketplace. Copy and code specialized to robot labor, and the public name became The RSE (The Robot Services Exchange). On 3 December 2025 registration began requiring user_type ∈ {demand, supply}, which is still set once and is still a single role. Demand’s public identity is a username; supply’s is meant to be a seat when one is assigned. On 11 August 2026 the marketing host moved to therobotservicesexchange.com. The API host, rse-api.com, was left alone, which is the practical reason robots and the website can evolve on different schedules.

4. Seats, blockchain, and a registrar

When the gate is on, a seat is what lets a provider call /grab_job and what gets stamped on the job as supply identity. It is not money: price and currency are recorded on the request, and the parties settle however they like. The cooldown that actually runs in production is still per account (900 seconds); the economic story on the SPA and investors pages is still one successful grab per seat per window, which is a gap rather than a contradiction, and it is called out again at the end. Three implementations differ in who holds the book and what a client has to show at grab time.

The Base contract did the things a chain is actually good at. Token ids were globally visible and not held in our database; the owner could revoke and unrevoke; grab used a 15-minute in-process cache so a successful match did not pay an eth_call on every request. Soulbound was an attempt to treat seats as licenses rather than tradable pictures, and it did that by reverting any transfer. After that change, moving title still required the contract owner, which is the same trust assumption as Mickey keeping a book, except that operators also needed wallets, a public RPC, and an asset they could not sell. That is why the chain was removed on 14 September rather than patched further. The 17 September issuance went back to the 2025 object (a number, an owner, a 12-word phrase) and changed only the proof:

secret = SHA-256( phrase ‖ "|" ‖ YYYY-MM-DDUTC )  ∈ {today−1, today, today+1}

The construction is the same shape as TOTP with a period of 86,400 seconds and a ±1-step window, so a client whose clock is on the other side of midnight UTC still verifies. The phrase itself is never sent. The owner string on the request has to match the book, ignoring case. The split of the first 11,000 seats is the old seats.dat allocation under ordinary names: 1–1000 to Dr. Aftab, 1001–11000 to Amanda Jean. Enforcement is still a config flag, SEAT_VERIFICATION_ENABLED, which is false; remote (location_type=remote) grabs are written to skip the seat when the flag is turned on, which is the current stand-in for the old Silver band.

5. How the matching prompt changed

Grab still filters by location (and optional geohash), then asks whether the provider can do the job, then ranks by reputation alignment and price. The LLM sits only in that middle step, match_service_with_capabilities, as a classifier in front of the sort. Four prompts were used; the failure modes moved with the wording, which is why they are listed rather than paraphrased into a single “the matcher got better” sentence.

ModelOutputRule
Aug 2025 Claude 3 Haiku, SDK YES / NO YES only if the provider can definitely fulfill the request; partial overlap is NO.
Oct 2025 OpenRouter (free, then paid fallback) YES / NO Same binary; if the model is silent, keyword overlap of at least two tokens.
Later, pre-Sep 2026 OpenRouter YES / NO “Be lenient”: a plausible chance is YES. Cross-domain false positives show up in tests.
10 Sep 2026 OpenRouter, max 8 tokens 0–10, grab if ≥ 7 Twelve domain lexicons; disjoint non-empty domains score 0 without an LLM call.
You score whether a provider can perform THIS exact job. Reply with one integer 0-10. 0-3: different domain (chef vs construction vs UAV/defense vs nursing vs lawn). 7-10: clearly has the skills or equipment for this job. Do not score 7+ across domains. Score:

The twelve domains in the current lexicon are culinary, delivery, health, landscaping, construction, defense, software, finance, pets, events, hazmat, and emissions. If both the job and the capabilities match a non-empty domain set and those sets are disjoint, the score is 0 and the model is not called; that is what makes “a chef is not a steel erector” a constraint rather than a suggestion in the prompt. The live suite is 34 cases and currently 33/34. The remaining false positive is adjacent-domain (aerial survey), which those lexicons do not separate.

6. What is actually running

Production is Flask and gunicorn on one DigitalOcean droplet, with nginx terminating TLS on a floating IP. Objects live in Spaces. Because gunicorn workers do not share memory, in-process caches are short on purpose: two seconds for accounts and jobs, so a sign or a party update is not served stale from another worker. There is still no relational store. The seat book is seats/_index.json plus one JSON file per seat; the index for 11,000 seats is about 500 kB, which is fine at this N and is not an argument that the same layout would hold a billion seats (the 2035 planning figure on the investors page).

Some of the code around the loop came and went. A rideshare UI was added and later removed. Comms and cooperation APIs were deprecated and then restored, with grab kept off the website. Phantom and ETH linking lasted until the registrar cutover. What stayed from July 2026 is the extra structure that does not change matching: demand and supply parties on a job, campaigns that turn bulk demand into ordinary jobs, agent bearer tokens under a parent account, an append-only activity log, and public portfolios. The taxi example is the intended robot client: poll grab with a geohash whitelist, talk on the job channel, sign. Nearby publishes pins with Gaussian noise (σ set by a privacy dial), stable per entity and UTC day so the point does not jitter on refresh.

8. What is still open

The daily hash is implemented and tested; turning it on is SEAT_VERIFICATION_ENABLED. Remote software stays ungated when that happens. The 11,000 founding seats are for physical and hybrid density, which is the scarce side. Cooldown is still per account, so many logins holding many of Aftab’s or Amanda Jean’s seats can still grab in parallel; a last_grab_at on the seat record would be the straightforward way to make the SPA’s “one grab per seat per window” true in the API. The 0–10 score is ordered but not calibrated, and the remaining false positive is adjacent-domain, so the next measurement that would actually change the prompt is a confusion matrix over the twelve lexicons rather than another adjective in the instructions. A chain could come back later as a mirror of the registrar. Using it as the book was the experiment that already ran.
